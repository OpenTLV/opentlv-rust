## [Unreleased]

### Changed

- Validate registry-style builds of the released `v0.1.0` archives: a clean `cargo package --workspace --locked` reproduces both byte for byte, `opentlv-sys` contains its build script and Core selection files, and consumers outside the workspace resolve the unchanged archives through a local Cargo registry and build, run and link verified Core `0.8.0` with all five feature sets on Linux and Windows. A new Full CI `consumer` check runs these builds on Linux, Windows and macOS stable with the archives of the same run, the quality gate requires them, and the `package` check rejects an archive without its build files. Record the consumer requirements: a default build needs an authenticated GitHub CLI and network access even with `OPENTLV_LIB_DIR`, so a clean machine and docs.rs cannot build the crates; CMake and a C compiler are needed in practice, because no Verified Binary was selected; cross compilation is not supported; and a Visual Studio build on Windows allows at most 49 characters in the Cargo target directory, or 47 with `--release`. Nothing was published. (#38)
- Validate the crates.io identities and the released `v0.1.0` archives of `opentlv-sys` and `opentlv`: both names are free with no owners yet, and metadata, license, dependencies and file lists match the tag. The `package` check also rejects an archive whose description, keywords, categories, edition, `rust-version`, `links`, build script, features or `publish` setting differs from the registry identity. Record that these archives must not be published, because their documentation says the crates are unpublished and docs.rs cannot build them, so the first crates.io version needs a new version. Nothing was published. (#37)

### Fixed

- List `tests/codec_abi_probe/` in the packaging document's `opentlv-sys` archive contents, which the archive already contained. (#37)

### Added

- Add the manual `Rust crates.io` workflow, which publishes the crate pair of an existing GitHub release after approval of the protected `crates-io` environment; nothing was published. Before any upload, and again after the approval, `scripts/crates_io.py` requires a dispatch from `main` with `main` and the tag at the same commit, an environment with a required reviewer, no administrator bypass and only `main` as its deployment branch, a recorded approval, the attested assets of the public release with their complete Full evidence and quality gate, and crates.io ownership of existing crates. `opentlv-sys` is uploaded first and must be served before `opentlv` follows. Because Cargo packs the crate again, each `cargo package` must reproduce the tested digest before its `cargo publish`, and the index entry and download must have it afterwards; this reproduction was measured on the `v0.1.0` assets. Versions already on crates.io are never replaced, so a retry uploads only what is missing. Trusted Publishing is used once both crates exist; as crates.io requires a token for the first version of a crate, that first publication uses an environment secret which is removed afterwards. The environment and token are not configured yet, and hosted publication has not run. (#39)

## [0.1.0] - 2026-10-28

### Changed

- Prepare the first standalone Rust release as `0.1.0` for both crates, replacing the unpublished `0.7.1` migration version independently of Core. Pin Core `v0.8.0` at `345c77acb29266036df5f27d04ce315bb61853cc` and require its authenticated release artifacts in default builds; document Python and GitHub CLI requirements. Add a manual GitHub release workflow that requires Main on the exact commit and same-attempt verified Full evidence, publishes the tested crate pair with checksums and attestations, and verifies the tag, notes and uploaded assets before publishing. Include verified-binary compiler probes in CI evidence. crates.io publication remains separate. (#33)
- Normalize Rust licensing and community policies to the Workspace reference: `REUSE.toml` and `LICENSES/MIT.txt` cover every file, listing documentation, data, `Cargo.lock`, the byte-preserved migration evidence and the C ABI probe imported from Core by exact path, and the Cargo manifests and Git configuration gain SPDX headers. Source quality runs `reuse lint`, and licensing regression tests reject glob or stale annotations, a license text differing from `LICENSE` and OpenTLV as a copyright holder; an optional pre-commit configuration runs the same lint with whitespace, YAML, JSON and TOML checks. The README, development guide and packaging document state Marek Cingel's copyright, contributor ownership, the MIT notice for binaries that link Core and the shared `OpenTLV/.github` contribution, conduct, security and support policies. (#31)
- Record the migration completion: original and final commits, the Core dependency identity, the baseline comparison, hosted PR, Main and Full runs, packaging, Core cleanup compatibility, documentation notification and workspace integration evidence, with known limitations and deferred follow-up work; the README and quality gates no longer describe Core's removed `bindings/rust` and Rust workflow as pending cleanup. (#7)
- Own the Rust user and development guides as standalone manuals for the OpenTLV documentation portal: setup from an opentlv-rust checkout with Rust 1.82 and the pinned Core, all three Cargo features including `nfc`, the independent `0.7.1` crate version, the current CI, local workspace development and contribution routing, with examples linked from this repository and Core references routed to its current documentation; technical content and the frozen migration evidence are preserved. - Move the Cargo workspace from the inherited `bindings/rust/` to the repository root, with `opentlv-sys/` and `opentlv/` as top-level crates; CI, the packaging check, tests and documentation use the new paths, and a regression test rejects the old layout in the build configuration. Crate sources, public API, Cargo features, `Cargo.lock`, native linking and the frozen migration inventory are unchanged. (#5)

### Added

- Complete and gate the generic Core API: `ReaderDiagnostic`, `DiagnosticMetadata`, `CodecDiagnostic`, `SchemaDiagnostic`, `WriterDiagnostic` and `ProgramError` gain `path_text()`, which formats the owned enclosing path through Core's `tlv_diagnostic_path_string()`, such as `"6F > A5"`, ending in `" > ..."` when truncated, and `opentlv-sys` declares the function. `tlv_location_translate` joins the API coverage ignore list with its reason: Rust entry points report Core's coordinates in the exact slice they receive and never add an origin. `ci/api-coverage.json` lists `core` as `complete`, so `Core API coverage` fails when a core symbol is neither referenced nor ignored or an ignore pattern matches nothing, after writing and uploading its report, and is now a `Rust quality gate` prerequisite instead of an informational job. The Core API coverage record (`docs/validation/api-coverage.md`) is the reviewed baseline for Core pin updates: every core header with its public Rust API and binding tests, the exclusions, the limitations and the update procedure. Core coverage of Core 0.7.1 is 215/215 (100.0 %) with 82 ignored. (#23)
- Complete the generic Codec and wire Generator APIs against pinned Core: exact-width unsigned and minimal signed integers, bytes, IPv4 addresses and lists, configured ASCII text and packed digit strings, Schema-constrained numbers, and complete-sequence structure codecs with Rust conversion closures. Borrowed results retain input lifetimes; failures retain native diagnostic causes. `Generator` owns candidate tags, borrows the Format and exposes deterministic seed/index replay with explicit output and workspace bounds. Add C ABI probes, binding contract and lifetime tests, `value_codecs` and `generate` examples, and a per-header inventory with intentional exclusions; core symbol coverage rises from 194/217 (89.4 %) to 214/216 (99.1 %), without extending protocol-specific Builtins parity. (#22)
- Track Document nodes across edits and reuse Query programs through Core: `Document::revision()` counts successful edits and `retire_epoch()` the edits that retired existing nodes (`tlv_document_revision()`, `tlv_document_retire_epoch()`). `Node::handle()` returns a `NodeHandle` that is not tied to a borrow, and `Document::resolve()` and `resolve_mut()` return its node while it is still in the Document, checked with Core's never-reused identity through `tlv_document_node_identity()`, so an erased or retired node resolves to `None` even when its address is reused. `Node::source_location()` returns the original offset and header length as a `DocumentSourceLocation` (`tlv_node_source_location()`), and `Document::visit()` visits every path match as a node (`tlv_document_query_visit()`). Encoding in the Document's own Format calls `tlv_document_encode()`, `tlv_document_encoded_size()`, `tlv_node_encode()` and `tlv_node_encoded_size()`, so `Document` no longer stores a Format pointer. `QueryProgram::compile()` with static names compiles directly through `tlv_query_compile_scratch()` and `tlv_query_compile()`, while a `resolver` keeps checked preparation and commit; both produce the same image. `QueryProgram::open_plan()` validates an image's native plan without the Query frontend (`tlv_query_plan_open()`), and `plan_info()` reads a program's requirements from its plan (`tlv_query_plan_info()`). `QueryExecution::reset()` resets in place through `tlv_query_exec_reset()`, keeping the program, providers, workspace and budgets; `next_result()` pulls through `tlv_query_result_next()`; `visit_document()` visits the remaining Document results through `tlv_document_query_program_visit()`; and Document evaluation without `value_capacity` discovers the Value snapshot with `tlv_document_query_value_size()` and reuses the discovery output as the snapshot, instead of measuring the Document separately and staging a second copy. `QueryProvider::number()` decodes NUM, BCD or DATE Values with a `NumberCodec` through `tlv_query_codec_decode()`, without a Rust callback, and `Query::visit_buffer()` visits the matches of a path in complete input without a Reader (`tlv_query_visit_buffer()`). (#21)
- Check structural schemas once and constrain decoded values: `StructureSchema::check()` checks the definition through `tlv_schema_prepare()` and returns a `CheckedStructureSchema` that borrows the schema and validates through `tlv_schema_validate_checked()` and `tlv_schema_validate_all_checked()` without repeating the check; `check_definition()` runs `tlv_schema_check()` alone, and Schema diagnostics are initialized with `tlv_schema_diagnostic_init()`. `ValueConstraint` builds a range, allowed-value or named-number constraint checked by `tlv_value_constraint_check()`, validates decoded values (`tlv_value_constraint_validate()`) and looks up named numbers (`tlv_value_constraint_name()`). `opentlv-sys` declares the new Document, Query, Schema and value constraint functions and types. The new `batch` example validates and queries several messages with one checked schema, one compiled program and one execution reset per message. `tlv_query_parse()`, the NUL-terminated form of `tlv_query_parse_n()`, is in the API coverage ignore list with its reason, so every `tlv/document`, `tlv/query` and `tlv/schema` symbol except the `tlv/schema/number.h` codec callbacks is referenced or ignored; core coverage of Core 0.7.1 is 194/217 (89.4 %). (#21)
- Read single elements and pull Reader elements through Core's own entry points: `read_element(data, format)` returns an `Element` and the consumed byte count through `tlv_read_diag()`, borrowing the Format only for the call, and `read()` decodes once through `tlv_read_source_diag()` instead of opening a Reader; both fail with a `ReaderError` that owns the `ReaderDiagnostic`, and with `Error::End` on empty input. `Reader::read_element()` pulls the next Element through `tlv_reader_next_diag()` without source metadata and, like `read_source()`, stays callable after an error, including `Error::NeedMoreData` before `set_input`; iteration uses it. `opentlv-sys` declares the three functions. NULL-diagnostic wrappers of bound `_diag` functions, the Tag/Value forms `tlv_write()` and `tlv_write_diag()` and `tlv_writer_copy_element()` are in the API coverage ignore list with their reasons, so every Reader, Writer, Tree Reader, Tree Writer and visitor symbol is referenced or ignored; core coverage of Core 0.7.1 is 167/218 (76.6 %). (#24)
- Compose custom Formats without C: `ComposedFormat::fields()` composes a `FieldComposition` of a `FixedIdentifier` or `VariableIdentifier` (with an optional `IdentifierPolicy`) and a `FixedLength`, `VariableLength` (with an optional `LengthPolicy`) or `EscapedLength`, with TLV or LTV order, Value or Tag-and-Value length scope, tag-only identifiers and `ConstructedBit` nesting, through Core's Fixed, tagged binary, Variable, escaped and generic field compositions. `ComposedFormat::packed()` composes a `PackedLayout` of two `PackedField` bit fields with an owned canonical identifier table, and `PackedField::read()`/`write()` extract and insert one bit field of a header integer. A `ComposedFormat` owns its descriptor, configuration and tables; clones share them and their native identity. Every format entry point (`Reader`, `TreeReader`, `Writer`, `TreeWriter`, `Document`, `decode`, `read`, the writer measurement functions and `StructureSchema` validation) now accepts any `FormatRef`: a builtin `Format`, `&FixedFormat`, `&OwnedFixedFormat` or `&ComposedFormat`; the `_fixed` variants remain as equivalents. Query uses composed Formats through `ProgramOptions::composed_format` and `QuerySchema::with_composed_format()`. `FormatRef` exposes `can_read()`, `can_write()`, `decode()`, `measure()`, `encode()` and `encode_into()`, failing with a `FormatError` that carries the Format's operation, region, offset, required size and field ranges. `opentlv-sys` declares the field encoding, composition and Format operation API, and a new composition ABI probe, `compose_abi`, checks their structure layouts against the C headers next to the unchanged imported probe. The new `compose` example uses one composed Format with Tree Writer, Tree Reader, Query and Document. Callback implementations installed by bound descriptor initializers are in the API coverage ignore list with their reason; core coverage of Core 0.7.1 is 164/235 (69.8 %). (#20)
- Report pinned Core API coverage in PR and Full CI as a non-blocking job: `TLV_API` functions and data referenced from the safe `opentlv` crate's `opentlv/src`, in total and per header, for core and builtins separately; added and removed symbols when a pull request changes the Core pin; and a documented ignore list for primitives and diagnostic producers in `ci/api-coverage.json`.
