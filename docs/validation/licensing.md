# Licensing and community policy validation

Local validation for [issue #31](https://github.com/OpenTLV/opentlv-rust/issues/31)
(part of [OpenTLV/opentlv#703](https://github.com/OpenTLV/opentlv/issues/703))
on 2026-10-27, on Windows 11 x64 and WSL Ubuntu, from the uncommitted working
tree. Local checks are not hosted workflow acceptance or release
authorization. Nothing was published.

## Ownership review

- All 31 commits of this repository and all 89 Core commits up to the source
  commit `476f1fbe` that touch `bindings/rust`, the Rust workflow or the two
  Rust guides are by Marek Cingel. There are no external contributions and no
  third-party notices to preserve.
- The 121 existing SPDX headers all read `MIT` and
  `Copyright (c) 2026 Marek Cingel`; none was changed. The three `LICENSE`
  files are byte-identical and name Marek Cingel.
- `Cargo.lock` lists only `opentlv` and `opentlv-sys`. No code is vendored, and
  no generated source is tracked: Cargo output in `target/` and the build
  script's `OUT_DIR` is ignored. `Cargo.lock` itself is generated by Cargo.
- Pinned Core `476f1fbe`: `LICENSE` is byte-identical to this repository's; all
  674 SPDX notices in its tree are `MIT` and `Copyright (c) 2026 Marek Cingel`
  (one Apache-2.0 string is test data of its header checker), and it has no
  vendored or third-party directories.

only from its annotation. The pre-commit configuration does not use
`reuse annotate`, which the Workspace reference runs for its own scripts: here
it would add Marek Cingel's notice to files of other contributors.

## Community policies

This repository has no contributing, conduct, security or support policy, no
issue templates and no PR template in `.github/`, the root or `docs/`, matching
the `opentlv-rust` row of the
[community defaults inventory](https://github.com/OpenTLV/.github/blob/main/docs/community-defaults.md).
None was added, so the `OpenTLV/.github` defaults apply. The README and the
development guide link the shared policies and keep the Rust build, test and
licensing instructions.
